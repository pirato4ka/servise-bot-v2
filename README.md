# Telegram Service Bot — Final v3 (CryptoBot + Reply-Bridge + Dynamic Admins)

Премиум бот для продажи услуг с акцентом на конфиденциальность. 

**Юзеру — украинский, админу — русский.**

### Функционал финала
1.  **Reply-Bridge:** Админ отвечает REPLY на заявку в админ-чате -> сообщение улетает юзеру от имени бота.
2.  **Продолжение диалога:** Любое сообщение юзера после анкеты форвардится в тред заявки.
3.  **Источник:** Поддержка deep-link `t.me/bot?start=channel_xxx` — пишется в заявке как "Источник".
4.  **Динамические админы:** Любой добавленный в админ-чат получает права автоматически. Отслеживается через `new_chat_members`, `left_chat_member`, `ChatMemberUpdated`. При каждом старте бот дополнительно сверяет таблицу админов с составом чата — **кто уже в группе, тот остаётся админом после перезапуска**.
5.  **Админ-панель `/admin`:** 
    - Статистика `/stats`, `/users`
    - CRUD услуг (➕ Добавить, ✏️ Редактировать, ❌ Удалить, 🔴/🟢 Вкл/Выкл)
    - Список админов
6.  **Оплата CryptoBot:** После заявки у админа кнопка `✅ Подтвердить`. При нажатии бот просит ввести договорную цену `100 USDT` -> создает **БЕСКОНЕЧНЫЙ инвойс** (без `expires_in`) и отправляет юзеру с кнопкой оплаты и проверки.

### Техстек
- Python 3.11 + aiogram 3.7
- SQLite + aiosqlite (таблицы: users, services, tickets, admins, invoices, messages_log, broadcasts, admin_messages)
- aiocryptopay для @CryptoBot

### Быстрый запуск (локально)

1. Клонируй папку, установи зависимости:
```bash
pip install -r requirements.txt
```

2. Создай `.env` из примера:
```bash
cp .env.example .env
nano .env
```
Содержимое `.env`:
```
BOT_TOKEN=123456:AAH...
ADMIN_CHAT_ID=-1001234567890
CRYPTO_BOT_TOKEN=12345:AAH... из @CryptoBot /pay
CRYPTO_BOT_IS_MAINNET=True
DB_PATH=bot.db
```

3. Запуск:
```bash
python -m app.bot
```

### Как получить токены

**BOT_TOKEN:**
- @BotFather -> /newbot -> копируешь токен

**ADMIN_CHAT_ID:**
- Создай группу, добавь туда бота и @userinfobot
- @userinfobot покажет ID группы (например -100...). Это ADMIN_CHAT_ID
- Сделай группу приватной, добавь туда всех админов

**CRYPTO_BOT_TOKEN:**
- Иди в @CryptoBot (прод) или @CryptoTestnetBot (тест, без реальных денег)
- /pay -> Create App -> вводишь название -> получаешь токен
- Для теста поставь CRYPTO_BOT_IS_MAINNET=False

### Флоу оплаты (договорная цена)

1. Юзер: выбирает услугу -> соглашается -> заполняет анкету:
   - 1/3 — как к нему обращаться
   - 2/3 — возраст (16-99)
   - 3/3 — кому требуется услуга: <b>Мне / Родному / Другу</b>
2. Админ-чат: приходит заявка с кнопками [Подтвердить] [Отклонить]
3. Админ: Нажимает Подтвердить -> бот просит "Введите цену: 100 USDT"
4. Админ: пишет цену -> бот через CryptoBot API создает инвойс без срока годности
5. Юзер: получает "Вашу заявку підтверджено! Договірна ціна: 100 USDT [Оплатити]" -> оплачивает в @CryptoBot
6. Юзер жмет "Перевірити оплату" -> бот дергает `get_invoices`
7. Оплата подтверждена -> админ уведомляется

### Важно
- Все ответы юзеру — от имени бота (анонимность админов сохранена)
- Все админские тексты — на русском, пользовательские — на украинском
- База bot.db хранится локально, **не коммить `.env` и `bot.db`** — они в `.gitignore`
- Если `.env` или архив с ним когда-либо попадал в репозиторий — перевыпусти токены:
  @BotFather → `/revoke`, @CryptoBot → `/pay` → новое приложение
- Для продакшена на сервере используй `systemd` или `docker-compose restart: unless-stopped`

## Двуязычные услуги

Одна услуга = одна запись в базе, но **все тексты хранятся в двух языках**:
`title_ua/ru`, `short_desc_ua/ru`, `terms_ua/ru`, `button_label_ua/ru`.

Что это даёт:

- UA-пользователь видит украинское название, описание, условия и кнопку; RU-пользователь — русские.
- Интерфейс целиком следует за языком: приветствие, шаги анкеты, кнопки отмены,
  варианты «Мне / Родному / Другу», кнопки оплаты CryptoBot и проверки платежа.
- `/lang` меняет язык на ходу — клавиатура услуг перерисовывается сразу.
- Нажатие кнопки работает на любом языке: услуга ищется и по UA-, и по RU-тексту.

### Как админу добавить услугу

`/admin` → 🛠 Услуги → ➕ Добавить услугу. Мастер из 10 шагов:

| Шаг | Что вводим |
|---|---|
| 1 | ID латиницей (`confidential_docs`) |
| 2 | Эмодзи |
| 3–4 | Название UA, затем RU |
| 5–6 | Краткое описание UA, затем RU |
| 7–8 | Условия покупки UA, затем RU |
| 9–10 | Текст кнопки UA, затем RU |

На любом «русском» шаге можно отправить **`=`** — бот подставит украинский вариант
(удобно, когда перевод не нужен или правится потом). `/cancel` прерывает мастер.

### Правка и копирование переводов

В карточке услуги (`/admin` → Услуги → услуга):

- **✏️ Редактировать** → выбор языка (UA/RU или эмодзи) → выбор поля
  (название / описание / условия / текст кнопки) → новое значение;
- **🇺🇦→🇷🇺 Скопировать UA в RU** — разом переливает все украинские тексты в русские;
- 🔴/🟢 — вкл/выкл, ❌ — удалить.

Текст кнопки проверяется на уникальность сразу в обоих языках.

### Миграция со старой базы

Старая таблица услуг была одноязычной. При первом запуске новой версии бот сам
переносит данные: старые значения попадают и в UA, и в RU, так что услуги
продолжают работать, а переводы админ дописывает через «Редактировать».
Ничего удалять или пересоздавать вручную не нужно.

### Запуск на хостинге (bothost и аналоги): права на базу

Самая частая ошибка при первом деплое:

```
sqlite3.OperationalError: unable to open database file
```

Причина: каталог с базой примонтирован хостингом **от root**, а процесс бота работает
под непривилегированным пользователем — SQLite не может создать файл.

Что сделано в этой версии:

1. Образ запускается **от root** (см. комментарий в `Dockerfile`), поэтому
   примонтированный том доступен на запись.
2. Каталоги `/data` и `/app/data` создаются в образе с правами `0777`.
3. `app/database/bootstrap.py` перед стартом реально проверяет, что файл базы
   создаётся и пишется. Если нет — бот автоматически уходит в запасной путь
   (`/app/data/bot.db` → `./bot.db` → `/tmp/bot.db`) и пишет в лог предупреждение:

   ```
   ⚠️ БД недоступна по пути /data/bot.db — пишем в /app/data/bot.db
   ```

Если в логах видно такое предупреждение — значит том смонтирован, но писать в него нельзя.
Проверьте в панели хостинга, что том подключён и путь совпадает с `DB_PATH`.
Данные в запасном каталоге могут не пережить пересборку контейнера, так что
это аварийный режим, а не постоянное решение.

## Что происходит при старте бота

1. `init_db()` — создаёт/мигрирует таблицы, включает WAL.
2. `sync_chat_admins()` — сверяет таблицу `admins` с реальным составом админ-чата:
   кто есть в группе — остаётся админом после перезапуска.
3. `load_active_broadcasts()` — поднимает активные рассылки, учитывая `last_sent_at`.
4. `invoice_watcher()` — раз в `INVOICE_POLL_INTERVAL` секунд проверяет неоплаченные счета
   в CryptoBot: оплата фиксируется даже если никто не нажал «Проверить оплату».

|---|---|---|
| `/start` | личка | выбор языка, меню услуг |

| `/cancel` | личка и админ-чат | отменить текущее действие |
| `/admin` | админ-чат | админ-панель |
| `/stats`, `/users` | админ-чат | статистика и последние 20 пользователей |
